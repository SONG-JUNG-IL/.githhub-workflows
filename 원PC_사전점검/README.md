# 원 PC 사전 점검 키트 (DICOCH 작업 환경 연계)

> 이 폴더에는 **개인정보·내부 경로·실제 데이터가 없다.** 일반 점검 도구와 양식만 둔다.
> 점검 결과와 인계 문서는 이 공개 저장소에 올리지 않는다.

## 1. 요구 상황 (이해 확인)

| 항목 | 현재 이해 |
|---|---|
| 작업 대상 | DICOCH 파이프라인(DICOM 생성 → 검증 → JPEG/IIIF 발행), CT/X-ray 비파괴 진단 데이터 |
| 데이터 위치 | 원 PC(폐쇄망 성격). 원본 영상은 외부로 반출하지 않음 |
| 연결 상태 | 외부 연결 불가이나 **Claude CLI는 동작**, **GitHub 연계는 불가** |
| 현재 진행 | 새 PC에서 Cowork 세션 2개로 작업 중 → T7로 원 PC에 **반납(인계)** 예정 (절차서 v2) |
| 목표 | 인계 완료 후 **원 PC에서 계속 작업**하고, 필요 시 클라우드 세션의 도움을 받는 구조 확립 |
| 제약 | 원 PC에서 직접 검토해야 확정되는 사항이 있음 → 이 키트로 **사전 준비** |

## 2. 운영 구조 (안)

| 구분 | 위치 | 용도 |
|---|---|---|
| 주 작업장 | 원 PC의 Claude CLI | 데이터 처리, 게이트 실행, 코드 수정 |
| 맥락 보존 | 21차 폴더 안 문서 (업무현황, 요청대장, 작업일지, 결정 기록, 전달문) | 새 세션이 이어받는 근거 |
| 버전 관리 | 원 PC 로컬 Git + T7 미러(bare) | GitHub 불필요 |
| 보조 | 클라우드 세션 | 데이터와 무관한 초안·설계, 결과는 텍스트로 가져가 적용 |

## 3. 원 PC 점검 절차

### 3-1. 자동 수집 (`precheck.ps1`)

1. 이 폴더를 승인된 방법으로 원 PC에 반입한다.
2. 터미널(Windows Terminal)에서 실행한다.
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\precheck.ps1
   ```
3. 바탕화면의 `precheck_결과_<시각>.txt` 를 열어 **식별 정보가 없는지 확인**한다.
4. 필요한 부분만 반출 승인을 받아 클라우드 세션에 붙여넣는다.

수집 항목: OS·Python·Git·Claude CLI 버전, CPU/RAM/디스크, 외부 연결 4곳(HEAD 요청), 프록시 환경변수(자격증명 제거), `pip freeze`.
수집하지 않는 것: 계정·토큰·키, 데이터 폴더, 파일 목록.

### 3-2. 수동 확인 체크리스트

| # | 확인 항목 | 확인 방법 | 결과 기록 |
|---|---|---|---|
| 1 | CLI 로그인 방식 (계정 / API 키 / 기관 계약) | CLI 시작 화면 또는 CLI 내 `/status` | ☐ |
| 2 | 원 PC에서 `claude remote-control` 실행 가능 여부 | 작업 폴더에서 시험 실행 (연결 대상 앱에서 세션 표시 확인) | ☐ |
| 3 | 연결 허용 범위 문서 확인 | 보안 부서 회신 (§4 질의서) | ☐ |
| 4 | `dciodvfy` 설치 위치 | `precheck.ps1` 결과 | ☐ |
| 5 | 원 PC Python 3.14.7 유지 여부 | `precheck.ps1` 결과 | ☐ |
| 6 | T7 드라이브 글자 | 탐색기 (절차서 4단계에서 사용) | ☐ |

### 3-3. 판정표

| 점검 결과 | 판단 | 다음 조치 |
|---|---|---|
| Anthropic 도달 가능, GitHub·PyPI 차단 | 현재 가정과 일치 | 원 PC 로컬 운영 확정 |
| PyPI 차단 | 오프라인 패키지 필요 | `pip freeze` 기준 wheel 목록 작성 (이미 `pip_freeze` 비교 절차 있음) |
| Anthropic 도달 불가 | CLI가 다른 경로로 연결 중 | 프록시/게이트웨이 확인 후 설계 재검토 |
| remote-control 불가 | 원격 조작 불가 | 로컬 CLI만 사용, 클라우드는 텍스트 전달 방식 |

## 4. 보안 부서 질의서 (초안)

> 제목: Claude Code(CLI) 사용 범위 및 데이터 전송에 관한 확인 요청
>
> 1. 원 PC에서 Claude CLI 사용 시 입력한 질의, 열람한 파일 내용, 명령 실행 결과가 외부 서비스(Anthropic)로 전송됩니다. 이 전송이 현행 보안 규정상 허용되는 범위입니까?
> 2. 허용 범위가 있다면 대상 자료 구분(소스코드, 로그, 문서, 영상 원본, 식별정보 포함 자료)별로 안내를 요청합니다.
> 3. 원격 조작 기능(`claude remote-control`)의 사용이 허용됩니까?
> 4. 외부 연결을 허용한 대상 주소(도메인) 목록과 변경 절차를 알려 주십시오.
> 5. 작업 결과(비식별 로그, 텍스트)를 외부 세션으로 옮기는 경우 필요한 승인 절차를 알려 주십시오.
>
> 기대 효과(정량): 반입·반출 왕복 작업 감소, 오류 재현·수정 주기 단축 (현재 수치는 실측 후 기재)

## 5. 운영 규칙 (제안)

| 규칙 | 내용 |
|---|---|
| 원본 영상 비열람 | CLI 세션에서 DICOM 원본·영상 픽셀은 열지 않고, 헤더·통계·로그만 다룬다 |
| 공개 저장소 금지 | 인계 문서, 점검 결과, 실제 경로·계정·세션 ID는 공개 저장소에 올리지 않는다 |
| 판 번호 | 한 환경에서만 올린다 (절차서의 기존 규칙 유지) |
| 반출 기록 | 반출 시 파일명, 시각, sha1을 대장에 기록한다 |

## 6. 한계

- `precheck.ps1` 은 PowerShell 환경이 없는 클라우드에서 작성하여 **실행 검증을 하지 못했다.** 첫 실행 시 오류가 나면 오류 문구만 알려 달라(경로·계정은 가려서).
- `claude remote-control` 의 제공 조건은 계정 종류와 기관 정책에 따라 다를 수 있다.
